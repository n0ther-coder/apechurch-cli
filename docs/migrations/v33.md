# CLI 33: independent residual bankroll stops

CLI 33 adds `--bankroll-stop` throughout the shared capital-control interface.
Commands using it require CLI 33 and a compatible control implementation.
Existing commands without the option retain their previous behavior; this
release does not automatically migrate scripts or change watcher scheduling.

| Previous command, option or output | CLI 33 command, option or output |
| --- | --- |
| `--bankroll A --bankroll-cap K` sets the initial budget and upper capital limit; there is no separate positive residual stop. | Add `--bankroll-stop S` to stop at initial allocation + cumulative actual net PnL ≤ S. Keep A as the sizing basis. For example, `--bankroll 120 --bankroll-stop 30 --bankroll-cap 240` stops at 30 remaining capital, not after losing the full 120. |
| Bare `bankroll-cap` or `bankroll-stop` tokens could be ignored as extra stateful operands in the generic play dispatch. | Both controls require the `--` prefix, in spaced or equals form. Bare spellings are rejected before validation or game dispatch, including direct stateful commands. JSON script option keys must also include `--`. |
| `--min-balance L` is a fixed wallet threshold; changing wallet balance can change the available sizing allocation. | It remains an independent wallet limit. The residual stop derives an additional floor C − H + S, recalculated at each fresh start and fixed within that invocation. |
| `--bankroll-cap K` stops only when remaining capital > K. | Unchanged. `--bankroll-stop S` stops at equality, requires S < H and S < K, and can also be used without a cap. |
| Terminal reason `min_balance` reports a wallet threshold; `bankroll_cap` reports excess capital. | New `bankroll_stop` reports exact residual `bankroll_ape`, `threshold_ape`, net `pnl_ape` and execution count. A separate wallet crossing can still report `min_balance`. |
| Child forwarding and resume retain an effective floor and the original allocation. | The stop-adjusted floor is forwarded; parent stop/cap thresholds are not. Saved runs validate the additional stop and retain the original allocation and floor. Changing the stop while resuming is rejected. |

For new game/bot implementations, use the shared helpers and regression
requirements in [BOTS.md](../BOTS.md#capped-allocation-runtime-contract) and
[BANKROLL_CAP.md](../BANKROLL_CAP.md). Actual additional costs, including failed
attempts, enter net PnL; included charges must not be subtracted twice.
